## Swapping in real back-end data

All app data lives in five JSON files in `src/data/`: `rules.json`, `lookups.json`, `changes.json`, `addresses.json` and `sources.json`. Replace them with real back-end output that matches the same data contract (same field names and value types).

`src/data/index.ts` is the single loader: every screen reads through it, and it validates each record with zod on load. Malformed records are skipped (never crash the app), logged to the console, and listed under "Data issues" on the `/audit` page.

The full field-by-field contract is in [docs/DATA_CONTRACT.md](docs/DATA_CONTRACT.md).

## Data: real engine output

The five files in `src/data/` are generated by `export_ui.py` in the navigator repository from the
Statute Street rule engine: rules extracted from the supplied law corpus (plus "no rule at this level"
findings), the engine's answer for every one of the 500 sample addresses as of 2026-10-01, the T1 to T5
change tests, the addresses with their geocoded legal city, and the source documents each rule cites
(with an `evidence_basis` of supplied_corpus, link_only_capture or manual_primary). They contain the
engine's output only, never the review key. Regenerate with `python export_ui.py` after a navigator
rebuild; the converter refuses to write anything that would fail the zod contract in `src/data/index.ts`.
Not legal advice.
